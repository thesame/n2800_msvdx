# Installation and reproduction

Use a dedicated N2800/Cedarview machine with a recoverable boot menu. The
backend supports only PCI 8086:0be2 with MSVDX revision 2.1.3.
The following commands are instructions for an authorized operator, not an
automatic installer. Preserve a stock Debian kernel and its initramfs.

## 1. Base SGX graphics stack

Use Debian 13 amd64 and the graphics source selected by
[graphics-dev.lock.json](../graphics-dev.lock.json): powervr_sgx dev commit
`fbc83abf423bd8761d046a6f10b94898647cf44e`. The matching base is Linux
`7.3.3-sgx`, package `7.3.3-sgx0~git20261116.547e4e6`. Kernel configuration,
gma500 patches and shared graphics UAPI are unchanged between those revisions.

Build the graphics kernel/headers, Mesa and SGX firmware using that repository's
`.github/workflows/powervr-sgx-deb.yml`, `drm/ci/deb-kernel.sh` and
`.github/workflows/mesa-debian.yml`. The lock records exact package hashes for
reproducing the selected integration; CI artifact availability is not guaranteed.
Do not assume a moving dev branch has the same ABI.

Install the matching amd64 packages and boot the SGX kernel. Verify a working
display and PowerVR SGX545 renderer before adding MSVDX. The exact headers,
configuration and Module.symvers must match the target, not just the release name.
Keep an independently bootable Debian kernel.

To rebuild the SGX module on a faster host:

```sh
git clone https://github.com/The1TrueJoe/powervr_sgx build/graphics-dev
git -C build/graphics-dev checkout fbc83abf423bd8761d046a6f10b94898647cf44e
target_headers=/absolute/path/to/exact/linux-headers-7.3.3-sgx
make -C "$target_headers" M="$PWD/build/graphics-dev/drm/powervr_sgx" \
  CONFIG_DRM_POWERVR_SGX=m CONFIG_DRM_POWERVR_SGX_GMA500=y -j8 modules
```

## 2. Native userspace and kernel module

```sh
sudo apt install build-essential pkg-config libva-dev libdrm-dev ffmpeg vainfo \
  mpv xz-utils python3 kmod patch
make -j2 check
python3 tools/build-gma500-powervr-sgx.py \
  --headers /usr/src/linux-headers-7.3.3-sgx --jobs 2
```

The kernel source baseline and compact H.264 command template are tracked in
this repository. The five original SGX gma500 patches are already applied to
the baseline; only the MSVDX hook is applied by the build helper. Do not apply
the five patches twice. The build requires no proprietary userspace libraries.
`build/kernel/build-manifest.json` records the module and input hashes; a build
receipt is not hardware validation.

The source baseline can be audited/reconstructed from Linux 7.3.3
(`linux-7.3.3.tar.xz` SHA256
`79c66dde66cd96877fcde8f7d36aec946b1f423d2b97b5a7b1751b75c764f3d1`)
plus `kernel/gma500-patches/` from the pinned graphics commit. The unmodified
DE2 decoder firmware and vendor license are under `firmware/`.

## 3. Stage, review and explicitly install

```sh
python3 tools/stage-debian.py
sudo python3 tools/install-msvdx-debian13.py --stage "$PWD/build/stage" --uid 1000
sudo install -m 0755 tools/cedar-vaapi tools/cedar-mpv tools/cedar-mpv-wayland \
  tools/cedar-with-libdrm tools/cedar-labwc tools/cedar-mpv-wayland-gpu /usr/local/bin/
```

Staging changes no system files. The installer requires running 7.3.3-sgx and
**does** replace that kernel's gma500 module, copy firmware/userspace, regenerate
its initramfs, create a dedicated default GRUB entry and enable the broker.
It does not reboot. It backs up the old module under the chosen stage directory's
`backup/`. Preserve that backup and the stage path. The script scopes decoder
options to its dedicated GRUB entry, not all gma500 modules on the machine.
Review its source before using it on another installation; its GRUB extraction
expects Debian's ordinary default SGX entry.

After an operator-approved reboot, verify:

```sh
uname -r
ls -l /dev/cedar-msvdx-test /dev/dri/renderD128
systemctl status cedar-decoder.service
dmesg | grep -E 'cedar-msvdx|microkernel started'
cedar-vaapi vainfo --display drm --device /dev/dri/card0
```

The kernel device stays root-only. The broker is root, accepts one explicit uid,
and exposes a uid-owned 0600 socket under `/run/cedar-decoder`. No world-writable
hardware node, browser sandbox disabling or raw-register access is needed for
the normal user demo. Root service configuration is generated by the installer;
`packaging/cedar-decoder.service.in` records the corresponding unit template.

## 4. Wayland GPU path (optional)

```sh
sudo apt install curl meson ninja-build
tools/build-libdrm-auxiliary.sh
sudo tools/build-libdrm-auxiliary.sh --install
```

This installs a private library into `/opt/cedar-libdrm`, with no global loader
change. Exit the old compositor and start `cedar-labwc -s alacritty` from the TTY.
Applications it starts inherit the library. Check `wayland-info`: both `wl_drm`
and `zwp_linux_dmabuf_v1` should be advertised. The launchers were installed in
step 3. `labwc`/`alacritty`/`wayland-utils` are additional package dependencies.

```sh
cedar-mpv-wayland-gpu --fullscreen demo/big-buck-bunny-720p-safe-h264.mp4
```

This keeps the required client `SGX_DEBUG=serial` workaround and starts muted.
Other asynchronous GPU clients remain unqualified. Ordinary `labwc` selects
the original system libdrm; `cedar-mpv-wayland` retains CPU `wlshm` output.

## 5. Check decoding

Stop other decoder clients first, then run as the broker's permitted user:

```sh
python3 tools/verify-decode.py demo/big-buck-bunny-720p-safe-h264.mp4
```

It compares the full requested frame count with software-reference NV12
(default 64, maximum 128), requires hardware completions and retirement of
owned resources, and fails on decode errors or quarantine. Use `--seek` for
open-GOP recovery and `--expect-rejection` for oversized controls. Raw 1080p
outputs need substantially more disk space; the verifier checks capacity. For
performance tests, keep rendering/audio/output identical, inspect all error
logs, and never count skipped or software-fallback frames as acceleration.


## Building on a faster host

Compile the kernel module on the host against the target's exact headers,
configuration and `Module.symvers`. The release string alone is insufficient.
`tools/build-gma500-powervr-sgx.py --headers /path/to/matching/headers --jobs 8`
records source, template and module identities in its build manifest.

Userspace also builds on the host using a Debian 13 sysroot. It needs target
libc headers/startup objects, libva/libdrm headers and libraries, and the loader.
Preserve the target's merged-usr library aliases and resolve kernel UAPI header
links into the sysroot. Add its `usr/include/x86_64-linux-gnu` to the compiler's
system include paths and its `usr/lib/x86_64-linux-gnu` to startup/library search
paths. For an amd64 Debian sysroot with the matching loader/library aliases:

```sh
target_sysroot=/absolute/path/to/debian13-sysroot
make -B -j8 all \
  CC="gcc --sysroot=$target_sysroot -isystem $target_sysroot/usr/include/x86_64-linux-gnu -B$target_sysroot/usr/lib/x86_64-linux-gnu/" \
  VA_FLAGS="-I$target_sysroot/usr/include/libdrm" \
  LDFLAGS="-L$target_sysroot/usr/lib/x86_64-linux-gnu"
```

This assumes the sysroot is already complete; it does not provision one. Check
ELF libc symbol requirements against the target before deployment. A successful
host-native compile is not proof of Debian 13 compatibility.

Use `tools/make-1080p-corpus.py OUTPUT` on the host to generate the profile,
crop, 64-slice and rejection probes. Generation alone does not qualify hardware.
Install the matching kernel, broker and VA library together; the new backing
layout is deliberately rejected by mismatched components.

The installed entry enables `msvdx_cpu_read_surfaces=1` for coherent image
readback. `cedar-labwc` and GPU player launchers retain `SGX_DEBUG=serial`.
For 1080p playback, start native Wayland from a TTY with
`cedar-labwc -s alacritty`, then run `cedar-mpv-wayland-gpu --fullscreen FILE`.
The launcher enables a decoder queue bounded to eight frames, 32 MiB and
0.5 seconds. User options override defaults. See [testing](TESTING.md) for
pixel comparisons, mixed-resolution restarts and presentation checks.
